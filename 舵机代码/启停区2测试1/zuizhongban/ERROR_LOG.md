# 错误记录

## [2026-08-28] 回退工程转向目标未完全归一化

**现象**：车辆在 BFS 转向或站点调整时可能沿累计 yaw 的长路径旋转；目标已经是当前角度时，首次 `Rotation()` 仍会先额外转约 5°。

**原因**：`TurnIMU()` 使用 `short target/error` 保存累计角度相加结果，接近 short 边界时会先溢出再归一化；`Rotation()` 在判断目标误差前先执行 IMU 健康检测动作。

**修复**：
- `TurnIMU()` 的目标角和误差改用 `int32_t`，统一通过 `NormalizeAngleError()` 归一化到 `[-180, 180]`。
- `Rotation()` 先计算归一化误差，误差在 ±2° 内直接返回，不再触发无意义的 5° 检测动作。
- IMU 仍需实际转动时保留原有健康检测、闭环修正和超限停止保护。

## [2026-07-19] IMU yaw 解析缺 int16_t 强转，导致 Rotation 绕远路/车身反转

**现象**：车到点位停下后，车头朝向不对，机械臂没对准工作区域

**原因**：imu.c 第62行 yaw 解析公式 `(ImuCmd[7]<<8|ImuCmd[6])/32768*180` 缺少 `int16_t` 强转。HWT101 输出的是有符号16位（-32768~+32767→-180°~+180°），缺少强转导致 yaw 永远在 0°~360°。跨 ±180° 时 Rotation 函数会算远路而不是近路

**修复**：
- `yaw_now = (float)((int16_t)(ImuCmd[7]<<8|ImuCmd[6])) / 32768.0f * 180.0f;`
- 参考：GongXun2025 冠军代码 HWT101.c 第154行

## [2026-07-18] hmi.c 编译报错 auto_str 未定义

**现象**：编译不通过，`hmi.c(90): error: #20: identifier "auto_str" is undefined`（VSCode 里 move.c 显示红波浪线是假报错，别被误导）

**原因**：Hmi_Func 里比对 `##auto` 指令用了 `auto_str[i]`，但文件顶部的字符串定义区漏写了这一行定义

**修复**：
- hmi.c 顶部补一行 `char auto_str[] = "##auto";`
- 顺手补上文件末尾换行，消掉警告 #1-D
- 经验：VSCode 波浪线 ≠ 真报错，以 Keil 编译日志 build_log.txt 为准

## [2026-07-18] Rotation 方向反复搞反

**现象**：调用 Rotation 后车子自转方向反了，或者一直转不停

**原因**：IMU 的 yaw 方向约定没搞清楚。最终确认：yaw 是 CCW+（逆时针变大），车顺时针转 = yaw 减小

**修复**：
- 顺时针转 90° 用 `Rotation(yaw - 90)`，不是 `yaw + 90`
- dir 映射：`error>0 → dir=1(CCW)`，`error<0 → dir=0(CW)`
- 以后**不要再改这两个约定**，实测确认过的

## [2026-07-18] Rotation 健康检查扰动导致误判

**现象**：健康检查 2° 太小，IMU 没检测到变化，判定 IMU 无效，走到回退模式无限自转

**原因**：健康检查 `Rotate(2, 0)` + 阈值 1°，电机实际转动可能不到 1°，误判 IMU 失效。回退模式 `Rotate(angle_desired, 0)` 中负数角度变成超大正数

**修复**：
- 健康检查恢复 5° + 阈值 2°，确保 IMU 能检测到
- 回退模式加保护：`if(ad<0) ad=-ad`

## [2026-07-18] RunMoveWithIMU 卡轮

**现象**：速度模式直行时轮子卡住不转

**原因**：MoveSolve 的方向约定和 RunMove 相反（w>=0 → dir=1 vs dir=0），且 Emm_V5 对 Vel_Control 指令响应不稳定

**修复**：
- 直行暂时不用速度模式，用位置模式 RunMove
- RunMoveWithIMU 保留在文件中备用，后续再调

## [2026-07-18] Rotation 步长不合理导致一卡一卡/精度不够

**现象**：90° 旋转时分很多小步，走走停停；或者转到差一点点不到位

**原因**：步长上限 15° 太小，容差 5° 太大，最小步 3° 太小

**修复**：
- 步长范围：2° ~ 45°
- 容差：±2°
- 主循环后加最终微调（误差≥1° 补一刀）
- Rotate 转速从 30 提到 50 RPM
- padding 从 800 降到 400ms

## [2026-08-09] Rotation 未归一化累计 yaw，导致导航前多转整圈

**现象**：车辆到达点位并调整机械臂朝向后，再次执行 BFS 导航时会多转一圈或数圈，随后才驶向下一个点位。

**原因**：`imu.c` 为了处理跨越 ±180°，把 `yaw` 展开成可超过一圈的累计角度；旧版 `Rotation()` 直接计算 `yaw_desired - yaw`。例如当前 `yaw=720°`、目标 `yaw_desired=0°` 时，物理朝向相同，但旧代码会得到 `-720°` 误差并执行多圈旋转。

**修复**：
- 新增 `NormalizeAngleError()`，每次闭环修正都把角度误差归一化到 `[-180°, 180°]`
- 误差计算改用 `int32_t`，避免 `short` 减法在累计角度较大时溢出
- 保持实测方向约定不变：`error>0 → dir=1(CCW)`，`error<0 → dir=0(CW)`
- 单次 `Rotation()` 最多修正 12 次、累计最多下发 270°；超过限制立即停止四个电机
- IMU 无效回退模式也根据当前角度选择最短旋转方向
- PC 回归测试覆盖 8 个跨圈和等价角用例，全部通过
- Keil 全量编译通过：`0 Error(s), 3 Warning(s)`；3 个警告均为原有不可达 `break`

## [2026-08-09] PowerShell 回归测试被执行策略拦截

**现象**：直接运行 `Tests/rotation_shortest_test.ps1` 时提示系统禁止运行脚本。

**原因**：Windows PowerShell 当前执行策略不允许直接执行本地 `.ps1` 文件。

**修复**：使用一次性命令 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tests\rotation_shortest_test.ps1` 运行测试，不修改系统全局执行策略。
